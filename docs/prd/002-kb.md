## TL;DR

Turn 6,500+ raw collector JSON/JSONL files into a queryable personal knowledge base that Claude can
search via MCP. **Scoped aggressively**: SQLite + FTS5 + MCP wrapper tools only. No Datasette, no
embeddings, no event modeling, no arbitrary SQL in v1. These come back in v2 only if real usage proves
v1 is insufficient.

## 1. Problem

### 1.1 Core user need (verbatim)

> 核心场景是想查 3 个月前某条推文这种，回过头重新做研究，我需要对原始数据归档，构建自己的知识库。

Translation: find historical items (especially tweets) from months ago for re-research. This is **not**
a real-time dashboard, not a disaster recovery story, not a vector-AI memory system. It is **trustworthy
historical retrieval**.

### 1.2 Current state

Data sits in 6,500+ files across 5 directories in `~/.local/deep-daily-daily/data/`. No index. `grep` works for small
searches; not for 70 GB / 3-year projection.

| Source | Files | Size | PK | Daily growth |
|---|---|---|---|---|
| articles | 2,750 JSON | 11 MB | `id` hex | ~100 files |
| tweets | 3,666 JSON | 14 MB | `tw_<id>` | ~460 files |
| tweets-nas | 8 JSONL | **216 MB** (93% of total) | `tw_<id>` | 1 file × 65 MB |
| news-6551 | 77 JSON | 2.4 MB | `6551-<hex>` | 1 file/day |
| hackernews | 1 JSONL | 16 KB | `objectID` | 1 file/day |

Schema pain points that MUST be resolved:

1. Timestamp field names vary: `fetched_at` / `collected_at` / `time` / `created_at`
2. URL field names vary: `link` / `url` / `tweet_url`
3. **tweets/** and **tweets-nas/** overlap heavily (same tweet ID appears in both) — if modeled naively,
   users see every tweet twice
4. news-6551 files are nested by date+category, not flat arrays

### Goals

- **G1** "Find tweet from N months ago" works in < 5 seconds for a specific keyword
- **G2** Claude can query the KB in conversation via MCP with bounded, safe tool calls
- **G3** Raw files stay canonical. kb.db is 100% rebuildable from disk.
- **G4** Tweets from `tweets/` and `tweets-nas/` appear **once** with full provenance for both sources,

- **NG4** No arbitrary `sql_query` MCP tool. Safe wrapper tools only.
- **NG5** No restore-from-backup integration. Separate concern (PRD 001).
- **NG6** No PDF / webpage capture.
- **NG7** No cross-device sync.
- **NG8** No chunked embeddings. Moot: no embeddings in v1.
- **NG9** No Chinese tokenizer upgrade (jieba). Document as known limitation; upgrade only if query

## 4. Design

### 4.1 Principles

1. **Raw files are canonical.** kb.db exists only to index them. Safe to delete and rebuild.
2. **Trustworthy over impressive.** One correct row beats ten duplicated ones.
3. **Provenance is data, not two rows.** Tweets that appear in both `tweets/` and `tweets-nas/`
   collapse to one logical item with **both raw sources tracked in a side table**.
4. **Wrapper tools over raw SQL.** MCP exposes constrained, safe functions. SQL escape hatch is
   deferred.
5. **Observability is a feature.** `ingest_runs` + `ingest_files` tables tell you exactly what
   happened every night.

### 4.2 Data flow

```
~/.local/deep-daily-daily/data/           ← RAW LAYER (canonical)
├── articles/*.json
├── tweets/*.json
├── tweets-nas/*.jsonl
├── hackernews/*.jsonl
└── news-6551/*.json

       │
       │ deep_daily kb ingest  (daily 04:00 via launchd, with lockfile)
       ↓

~/.local/deep-daily-daily/data/kb/kb.db   ← INDEX LAYER (rebuildable)
├── items              one row per logical item
├── item_raw_refs      provenance side table (1-to-many per item)
├── items_fts          FTS5 virtual table
├── ingest_runs        observability
├── ingest_files       per-file status + watermark
└── meta               schema_version, last_ingest_ts, etc

       │
       ├─► deep_daily kb mcp      MCP stdio server for Claude Desktop

       └─► deep_daily kb stats    Health + counts

                  (deep_daily kb serve = deferred to v2)
```

### 4.3 Schema

```sql
-- Main table. One row per logical item.
-- For tweets present in both tweets/ and tweets-nas/, there is ONE row here
-- and TWO rows in item_raw_refs.
CREATE TABLE items (
  id             TEXT PRIMARY KEY,          -- "<source>:<native_id>" e.g. "tweet:2049476450554896478"
  source         TEXT NOT NULL,             -- 'article' | 'tweet' | 'news6551' | 'hn'
  native_id      TEXT NOT NULL,             -- original id from the source
  event_ts       TEXT NOT NULL,             -- ISO 8601 UTC, normalized across sources
  fetched_ts     TEXT NOT NULL,
  author         TEXT,                       -- handle / feed_title / hn author
  title          TEXT,
  body           TEXT,                       -- primary text content (displayed)
  body_zh        TEXT,                       -- Chinese translation if distinct
  url            TEXT,
  category       TEXT,
  relevance      INTEGER,                    -- 1-5 where available, NULL otherwise

  -- Provenance summary (fast filtering; details live in item_raw_refs)
  has_curated    INTEGER DEFAULT 0,          -- tweet present in tweets/
  has_bulk       INTEGER DEFAULT 0,          -- tweet present in tweets-nas/
  preferred_src  TEXT NOT NULL,              -- 'curated' | 'bulk' | 'single'

  -- Bookkeeping
  first_seen_ts  TEXT NOT NULL,              -- when we first ingested this item
  last_seen_ts   TEXT NOT NULL               -- last ingest run that confirmed it
);

CREATE INDEX idx_items_ts       ON items(event_ts DESC);
CREATE INDEX idx_items_src_ts   ON items(source, event_ts DESC);
CREATE INDEX idx_items_author   ON items(author);
CREATE INDEX idx_items_category ON items(category) WHERE category IS NOT NULL;

-- Raw provenance side table. 1 item -> 1+ raw file references.
-- For tweets merged from curated + bulk: 2 rows per item_id.
-- For all other sources: 1 row per item_id with provenance='single'.
CREATE TABLE item_raw_refs (
  item_id        TEXT NOT NULL REFERENCES items(id) ON DELETE CASCADE,
  provenance     TEXT NOT NULL,              -- 'curated' | 'bulk' | 'single'
  raw_path       TEXT NOT NULL,              -- absolute path to source file
  raw_locator    TEXT,                        -- line number for JSONL, NULL / "." for single-record JSON
  raw_hash       TEXT,                        -- sha1 of record JSON, for drift detection
  raw_mtime      TEXT,                        -- file mtime at ingest time (ISO UTC)
  first_seen_ts  TEXT NOT NULL,
  last_seen_ts   TEXT NOT NULL,
  PRIMARY KEY (item_id, provenance)
);

CREATE INDEX idx_raw_refs_path ON item_raw_refs(raw_path);

-- FTS5 virtual table, content-linked for zero-copy.
CREATE VIRTUAL TABLE items_fts USING fts5(
  title, body, body_zh, author,
  content='items',
  content_rowid='rowid',
  tokenize='unicode61 remove_diacritics 2'
);
-- Triggers keep items_fts in sync with items (ai/ad/au).

-- Ingest observability.
CREATE TABLE ingest_runs (
  run_id        INTEGER PRIMARY KEY AUTOINCREMENT,
  started_ts    TEXT NOT NULL,
  finished_ts   TEXT,
  mode          TEXT NOT NULL,              -- 'incremental' | 'rebuild'
  sources       TEXT,                         -- comma-separated if restricted
  files_scanned INTEGER DEFAULT 0,
  files_skipped INTEGER DEFAULT 0,            -- unchanged per watermark
  files_ok      INTEGER DEFAULT 0,
  files_failed  INTEGER DEFAULT 0,
  rows_inserted INTEGER DEFAULT 0,
  rows_updated  INTEGER DEFAULT 0,
  rows_refs_added INTEGER DEFAULT 0,          -- new provenance rows (tweet first appearing in bulk)
  ok            INTEGER                       -- 1 success, 0 failure, NULL in-progress
);

-- Per-file ingest state. Primary watermark store.
CREATE TABLE ingest_files (
  path         TEXT PRIMARY KEY,              -- absolute file path
  source       TEXT NOT NULL,
  last_run_id  INTEGER REFERENCES ingest_runs(run_id),
  last_mtime   TEXT NOT NULL,                 -- ISO UTC
  last_size    INTEGER NOT NULL,              -- bytes
  rows_seen    INTEGER DEFAULT 0,
  status       TEXT NOT NULL,                 -- 'ok' | 'error' | 'skipped'
  error        TEXT
);

CREATE TABLE meta (
  key    TEXT PRIMARY KEY,
  value  TEXT
);
-- seed: schema_version, last_ingest_ts, created_ts
```

**Why `item_raw_refs` as a side table** (Oracle v2):
- A merged tweet has TWO authoritative raw records (one in `tweets/`, one in `tweets-nas/`). A single-pointer
  design on `items` would force us to pick one and lie about the other.
- Future-proof: if we ever add a third source for the same item (e.g., a tweet also captured by another
  collector), we insert another row, no schema change.
- `get_item` can return all provenance cleanly.

**Why no full raw JSON column** (Oracle v1 & v2): doubles storage for bulk-heavy sources (tweets-nas),
violates "raw files are canonical" principle, makes DB couple to data we can always re-read. We store
only normalized fields + pointers. `raw_hash` lets us detect drift between runs.

**Why prefixed `id` + separate `native_id`**: composite keys are annoying for MCP tools and joins; prefixed
id is a single string Claude can pass around; `native_id` preserves the original for round-trip.

### 4.4 Tweet dedup: deterministic field-by-field precedence

Replaces "if richer" with explicit rules. Same tweet id from `tweets/` (curated) and `tweets-nas/` (bulk)
produces ONE `items` row and TWO `item_raw_refs` rows.

**Merge algorithm**:

```python
# Pseudocode — implementation in kb/dedup.py
def merge_tweet(existing: Item | None, incoming: NormalizedTweet, source: str) -> Item:
    """
    source: 'curated' (from tweets/) | 'bulk' (from tweets-nas/)
    """
    if existing is None:
        # First sighting: create item with provenance flags
        return new_item(incoming, has_curated=(source=='curated'),
                                   has_bulk=(source=='bulk'),
                                   preferred_src=source)

    # Existing row — merge fields by deterministic precedence
    merged = existing.copy()

    # Update provenance flags
    if source == 'curated':
        merged.has_curated = 1
    elif source == 'bulk':
        merged.has_bulk = 1

    # Precedence rules — strictly by (field, source)
    CURATED_OVERRIDES = {'body', 'body_zh', 'title', 'author', 'relevance', 'category'}
    BULK_FILLS_WHEN_NULL = {'body', 'body_zh', 'title', 'author', 'url', 'relevance', 'category'}
    MUST_MATCH_OR_WARN   = {'native_id', 'event_ts', 'url'}

    for field in MUST_MATCH_OR_WARN:
        existing_val = getattr(existing, field)
        incoming_val = getattr(incoming, field)
        if existing_val and incoming_val and existing_val != incoming_val:
            log_warn(f"field drift on {existing.id}: {field} existing={existing_val!r} "
                     f"incoming={incoming_val!r} (source={source})")
            # Do NOT overwrite — first-write-wins for these fields.

    if source == 'curated':
        # Curated always overrides bulk for display fields
        for field in CURATED_OVERRIDES:
            val = getattr(incoming, field)
            if val is not None:
                setattr(merged, field, val)
        merged.preferred_src = 'curated'

    elif source == 'bulk':
        # Bulk only fills nulls; never overwrites curated
        for field in BULK_FILLS_WHEN_NULL:
            if getattr(merged, field) is None:
                val = getattr(incoming, field)
                if val is not None:
                    setattr(merged, field, val)
        # preferred_src stays as-is (usually 'curated' if already set)

    merged.last_seen_ts = now_iso()
    return merged
```

**Decision matrix** (cheatsheet):

| Field | curated (tweets/) overrides? | bulk (tweets-nas/) fills null only? | Drift warning? |
|---|:---:|:---:|:---:|
| `native_id` | — | — | yes (must match) |
| `event_ts` | — | — | yes (must match) |
| `url` | — | fill if null | yes (must match when both present) |
| `body` | ✓ | ✓ | — |
| `body_zh` | ✓ | ✓ | — |
| `title` | ✓ | ✓ | — |
| `author` | ✓ | ✓ | — |
| `relevance` | ✓ | ✓ | — |
| `category` | ✓ | ✓ | — |
| `preferred_src` | set to 'curated' | leave existing | — |
| `has_curated` | set 1 | — | — |
| `has_bulk` | — | set 1 | — |

**`item_raw_refs` upsert**: on each sighting, upsert a row with `(item_id, provenance)` as PK. Always
update `raw_path`, `raw_locator`, `raw_hash`, `raw_mtime`, `last_seen_ts` — raw files can move or be
rewritten, and we always want the freshest pointer.

**Ingest-order independence**: curated-first-then-bulk and bulk-first-then-curated converge to the same
final state. Verified by IT-3 and fuzz test in Milestone 2.

### 4.5 Incremental ingest: watermark rules

**Per-file skip rule** — before opening a file, consult `ingest_files`:

```
Let disk_mtime = os.path.getmtime(path), disk_size = os.path.getsize(path)
Let prev = ingest_files[path]  (row keyed by absolute path)

If prev EXISTS AND prev.status == 'ok'
              AND prev.last_mtime == iso(disk_mtime)
              AND prev.last_size == disk_size:
    skip file entirely
    files_skipped += 1
Else:
    re-ingest the whole file (see below)
    update ingest_files row with new mtime/size
```

**JSONL files** (tweets-nas, hackernews): on change, re-scan the entire file. **No line-level incremental
in v1.** Reasons:
- Detecting appends vs rewrites reliably needs inode tracking + content hashing.
- `dedup.py` is already idempotent: re-ingesting every line against `items_fts` + `item_raw_refs` is
  O(N) but cheap (SQLite FTS5 handles 100k+ upserts/minute).
- Simpler failure model: if a file is corrupted partway through a run, next run re-tries cleanly.

**JSON files** (articles, tweets curated, news6551): single record per file, straightforward re-ingest.

**Rebuild mode** (`--rebuild`): ignore watermark, drop+recreate kb.db, scan everything. Expected
completion < 5 min on full dataset (tweets-nas/ is the long pole).

**Raw file disappears**: NEVER delete items. `item_raw_refs` row retains stale pointer; `get_item`
reports `raw_unavailable=true` at read time. `items` stays searchable via FTS. See §4.8.2.

### 4.6 Source-specific normalization

Implemented in `src/deep_daily/kb/normalize.py`. One function per source, all returning the same
`NormalizedItem` dataclass.

| Source | event_ts source | url source | body source | Notes |
|---|---|---|---|---|
| article | `fetched_at` | `link` | `summary_zh` | `insight_zh` concatenated into body if present |
| tweet (curated) | `event_time` | `tweet_url` | `content` | `reference_content` appended for replies |
| tweet (bulk JSONL) | `collected_at` (UTC+8 → UTC) | `tweet_url` | `content` | Same logical item as curated |
| news6551 | `time` | `link` | `title` (no body available) | Parent file category → `category` field |
| hn | `created_at` | `url` | `title` (no body) | `points` and `num_comments` in category as `hn:points=N` |

Timestamp normalization rules documented inline with unit tests.

**Schema-change policy** (Oracle Q5): adapters are **field-explicit**. If a source adds a new JSON field,
we ignore it at ingest time; it remains in the raw file for re-ingest if we ever add handling. If a
source removes or renames a field we depend on, the adapter fails loudly for that file (logged to
`ingest_files.error`, `status='error'`), other files continue.

### 4.8 MCP tool surface (v1)

Three tools, minimal and safe, with a fully specified result contract.

#### 4.8.1 `search_text`

```python
search_text(
    query: str,                                        # FTS5 query string
    source: Literal['article','tweet','news6551','hn'] | None = None,
    start_date: str | None = None,                     # ISO 8601 date inclusive
    end_date: str | None = None,                       # ISO 8601 date inclusive
    author: str | None = None,                         # case-insensitive substring match
    limit: int = 20                                    # 1..100; clamped
) -> list[ItemSummary]
```

**Result contract**:
- Always sorted by `event_ts DESC` (most recent first). Tie-break: `id ASC` (deterministic).
- `limit` clamped to `[1, 100]`; default 20. Values outside range are silently clamped, not rejected.
- `author` filter: case-insensitive substring match against `items.author` (`LOWER(author) LIKE '%val%'`).
  For exact-handle search, put the handle in `query` (e.g., `query="balajis RWA"`).
- `query` is an FTS5 MATCH expression. Supports `AND`, `OR`, `NOT`, phrase quotes. Runs against
  `title + body + body_zh + author`.
- `start_date`/`end_date`: inclusive on both ends. Parsed as ISO 8601 date (`YYYY-MM-DD`); promoted to
  UTC range `[start T00:00:00Z, end T23:59:59Z]`.
- Snippet: generated via FTS5 `snippet()` with 200-char window, first match, `[...]` ellipses.
- Each result shape:
  ```json
  {
    "id": "tweet:2049476450554896478",
    "source": "tweet",
    "event_ts": "2026-02-14T03:12:45Z",
    "author": "balajis",
    "title": null,
    "snippet": "... RWA and Ondo are the real ...",
    "url": "https://twitter.com/...",
    "preferred_src": "curated"
  }
  ```
- Empty result → return `[]`, never raise.

#### 4.8.2 `get_item`

```python
get_item(id: str) -> ItemDetail | None
```

**Result contract**:
- Returns `None` if id not in `items`.
- Returns fully hydrated item with all normalized fields.
- Includes `raws: list[RawRef]` — one entry per `item_raw_refs` row, ordered by provenance:
  `curated` → `bulk` → `single`.
  ```json
  {
    "provenance": "curated",
    "raw_path": "~/.deep-daily-example/data/tweets/tw_2049....json",
    "raw_locator": ".",
    "raw_hash": "abc123...",
    "raw_mtime": "2026-02-14T03:15:02Z",
    "raw_unavailable": false,
    "raw_unavailable_reason": null,
    "raw": { ... parsed JSON from disk ... }
  }
  ```
- **`raw_unavailable=true`** when any of:
  - `raw_path` file does not exist on disk → `raw_unavailable_reason="file_missing"`
  - `raw_path` exists but JSONL `raw_locator` line number is out of bounds → `raw_unavailable_reason="locator_out_of_range"`
  - Re-read record's computed sha1 ≠ stored `raw_hash` → `raw_unavailable_reason="hash_mismatch"`
  - `raw_path` unreadable (permission denied etc.) → `raw_unavailable_reason="read_error: <errno>"`
- When `raw_unavailable=true`, `raw` is `null`; other metadata fields (`raw_path`, `raw_locator`,
  `raw_hash`, `raw_mtime`) remain populated for debugging.
- All provenance refs are always returned, even if some are unavailable. Caller decides what to do.
- Partial unavailability is fine: one provenance unavailable does not invalidate others.

#### MCP safety

- Connection opened with `?mode=ro` URI.
- `PRAGMA query_only=1` set on every session.
- Rejects `ATTACH`, `PRAGMA` changes, any mutation.
- All three tools use prepared statements; no string concatenation of user input.
- FTS5 `query` param is passed directly to MATCH; FTS5 syntax errors return empty result with log,
  not exception.

## 7. Open Questions (LOCKED)

Answers locked based on Oracle v2 review (ses_207f5a226ffeXVDlqhMs4XQ3G7):

- **Q1** Never delete ingested items, even if raw file removed?
  **Decision: yes, never delete by default.** Historical research wants durable recall; `last_seen_ts`
  marks staleness without destroying findability. `get_item` reports `raw_unavailable=true` when raw
  is gone (§4.8.2, U8, IT-6).

- **Q2** Raw pointer (`raw_path + raw_locator + raw_hash`) vs full JSON blob?
  **Decision: pointer, via `item_raw_refs` side table.** One pointer per provenance; merged tweets
  have 2 rows. Storage-lean, rebuildable, handles dual-source tweets cleanly.

- **Q3** Curated vs bulk preferred for same tweet id?
  **Decision: curated wins** for display fields (`body`, `body_zh`, `title`, `author`, `relevance`,
  `category`). Bulk fills nulls only. `preferred_src` records the choice. See §4.4.

- **Q4** MCP tool surface: `search_text` + `get_item` + `stats` sufficient?
  **Decision: yes, ship 3.** Anything more now is speculation. Add a fourth only if real usage patterns
  show a gap.

- **Q5** Raw schema changes handling?
  **Decision: field-explicit adapters; ignore unknown fields; fail loudly on missing-required fields**
  for that file only (other files continue). See §4.6.

- **Q6** Chinese FTS tokenizer: `unicode61` vs jieba?
  **Decision: `unicode61 remove_diacritics 2` for v1.** Good enough to validate usage. Upgrade to jieba
  only if AQ3/AQ5 real-world recall blocks work.

- **Q7** Embeddings / semantic search in v1?
  **Decision: fully deferred.** User's stated need is historical lookup, not semantic exploration. FTS5
  is enough until proven otherwise.

## 9. Risks

| Risk | Likelihood | Impact | Mitigation |
|---|:---:|:---:|---|
| tweet dedup bugs (same tweet appears twice) | High if naive | High (immediate distrust) | Explicit field-by-field merge (§4.4) + IT-1/IT-2 gates |
| Merged tweet loses provenance | Medium if single-pointer | High | `item_raw_refs` side table (§4.3) + IT-2 gate |
| "if richer" logic produces non-determinism | High if under-specified | Medium | Decision matrix in §4.4 replaces subjective rule |
| Chinese FTS low recall | High | Medium | Documented as known v1 limitation; jieba deferred to v2 |
| Incremental ingest misses updates | Low | Medium | Watermark = `(path, mtime, size)`; any change → full re-scan |
| Ingest crashes mid-run | Medium | Medium | `ingest_runs.ok=0` flag; next run picks up; `--rebuild` always works |
| Concurrent run (manual + cron) | Low | Medium | Lockfile at `state/kb-ingest.lock` with stale-PID recovery (mirrors PRD 001) |
| kb.db grows beyond FTS5 sweet spot | Low (70 GB is fine) | Low | Monitor DB size; revisit if > 50 GB |
| MCP tool surface too rigid for LLM | Medium | Medium | 3-tool starting set is small; add tools based on observed Claude usage patterns, not speculation |
| Raw file disappears between ingest and `get_item` | Medium | Low | `raw_unavailable=true` flag (§4.8.2, IT-6); item stays searchable |
| JSONL locator drifts after rewrite | Low | Medium | `raw_hash` is truth check; locator is a hint; IT-7 covers drift |
| User loses interest (abandonment) | Medium | High | Ship MCP by Milestone 4; M6 usefulness gate; kill-switch if zero real lookups |

## 13. Appendix: Decision Log

Tracking the "why not" for cut scope, so future revisits have context.

| Cut | Reason | Revisit trigger |
|---|---|---|
| Datasette | Not primary interface (user prefers MCP); extra process to debug | User reports wanting browser UI |
| sqlite-vec / embeddings | FTS5 handles 80% of "find keyword" queries; embeddings premature | FTS5 recall fails on real queries |
| `events` table | Second-system creep; adds snapshot/TTL semantic complexity | Real need for cross-source entity queries |
| Arbitrary SQL MCP tool | LLM context + table scans = brittle; wrapper tools safer | Wrapper tools insufficient after 2 weeks |
| Full raw JSON column | Doubles storage; violates canonical-raw-files principle | Never — design decision |
| Single raw pointer on `items` | Merged tweets have 2 authoritative sources; single pointer lies | Never — replaced by `item_raw_refs` |
| "If richer" merge rule | Non-deterministic; produces ingest-order-dependent results | Never — replaced by field-by-field precedence (§4.4) |
| Line-level JSONL incremental | Complexity > benefit; full file re-scan is fast enough | JSONL files grow > 1 GB each |
| Ollama default-on embeddings | Hidden dependency on Ollama install | Only if embeddings are added (v2.2) |
| jieba tokenizer | Extra C dep; unicode61 may be sufficient | AQ3/AQ5 Chinese recall fails in real use |
| Cross-device sync | M4-only machine; no current second host | M2 becomes research machine |
| M5 "queried at least once" | Measured curiosity, not value | Never — replaced by M6 real-lookups gate |
| AQ6 as acceptance | Raw SQL conflicts with "no SQL MCP" scope | Never — recast as IT-1/IT-2 internal tests |
